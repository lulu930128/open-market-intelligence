OMI v4 能力設計表
日期：2026-07-24
公開契約：omi.decision.v4
Capability Registry：omi.capability.registry.v1
Capability 數量：38

一、總結

1. OMI 的公開 AI 決策出口已收斂為 omi.decision.v4。
2. HTTP、SSE、repo MCP、standalone OMI_search、OMI Dock 與 Kuro preflight
   都送出或取得同一份 v4 canonical envelope。
3. Kuro/桌寵不是另一套 OMI contract。Kuro 模型自行把 v4 evidence/decision
   整理成可念稿、角色語氣與 TTS 內容。
4. v2/v3 只保留在 OMI backend 私有 builder、回歸 seam，以及 Kuro 舊聊天
   歷史的讀取相容；不能再由 public request 指定。
5. 「單一出口」指單一 decision contract，不代表刪除所有 /api/market/*
   data-plane routes。OMI backend 與自家 UI 仍可用專用 route 讀圖表/資料，
   外部模型的統一入口則是 omi.ask v4。

六、目前可以做到

[可以] 單一問題同時帶 target 與多個 intent，不再把「查 freshness」誤當成
       另一個標的。
[可以] 模型只選 quote.snapshot 的指定欄位，不必一次接收整包個股 context。
[可以] 針對 intraday/daily/history 設筆數，並設定總 response byte budget。
[可以] 缺 quote、intraday、daily、chips、fundamentals、crypto depth/derivatives
       時回傳單 capability、單 target 的 fill action。
[可以] 模型只執行選中的 fill action；backend 重新驗證 plan_id、action_id、
       target、tool、call count、timeout 與 cache-write policy。
[可以] 查台股個股、台股市場、自選股、指數、台指期、美股、日股、韓股、
       Crypto、資源商品、FRED macro、portfolio、source health。
[可以] 回傳 answer、decision、evidence、quality、manifest、limitations、
       execution、continuation、error 的固定 v4 結構。
[可以] 付費 OpenAI API 可作 OMI synthesis/report，但需 backend trust、
       API key 與 budget；MCP/Kuro 不接觸 API key。
[可以] 休市時回傳 latest_completed_session/final_snapshot，不冒充 live。
[可以] provider 失敗時回傳 cached/stale/partial/missing/provider failure，
       不把缺值轉成 0 或 ready。

七、條件式可以做到

[條件] 「即時」只有 provider 確實提供 event time、received/fetched time、
       session、timezone、age 且門檻通過時才成立。
[條件] require_live 可要求 live，但 provider 不連線或市場休市時會明確失敗/
       blocked，不會偽造。
[條件] 美股/日股/韓股 refresh 取決於 API key、provider quota、交易時段與
       release schedule。
[條件] Crypto 是 sampled snapshots/ohlcv/order book/derivatives，不是交易所
       逐筆永久 archive。
[條件] 台股市場量能同分鐘基線需要 minute history；樣本不足維持 partial。
[條件] portfolio valuation 只能在原幣別可靠彙總；沒有顯式 FX contract 時
       cross_currency_total 為 null。
[條件] OMI analysis/report 可用付費 LLM，但一般 read-only caller 不會因
       allow_llm=true 就自動取得權限。
[條件] standalone OMI_search 與 Kuro 已改成 v4 source code；實際常駐程序仍需
       重啟/重新載入後才會吃到新版本。

八、目前不能做到

[不能] 自動下單、券商帳戶操作、代替使用者執行交易。
[不能] 保證價格、報價、深度或指標永遠即時；資料源沒有就只能回缺口。
[不能] 用 health HTTP 200 代表資料新鮮、decision ready 或 provider 正常。
[不能] 任意 SQL、任意 table join、任意 dataset query DSL。
[不能] 讓 consumer 直接讀 OMI SQLite 或自己重做 freshness/market semantics。
[不能] 讓 MCP、Frontend 或 Kuro 改寫 OMI answer/decision 成另一套市場 contract。
[不能] 由 OMI 產出 Kuro 專用可念稿；該工作由 Kuro 模型/呈現層負責。
[不能] 無限制全市場 refresh、無界歷史回補或不透明付費 quota 消耗。
[不能] 把 unavailable/stale/partial 資料合成為 0、current、ready 或確定因果。
[不能] 目前直接查港股；HK symbol master/calendar/provider/freshness contract
       尚未完成。
[不能] 把 ADR parity 視為自動保證正確的套利價；ratio/FX/reference time 仍需
       版本化 metadata 與驗證。

九、consumer 讀取規則

1. 先看 status.readiness，不可只看 HTTP 200、SSE done 或 MCP isError。
2. 要顯示/朗讀結論時讀 answer；要做決策條件時讀 decision。
3. 所有資料可用性以 evidence.quality 與 evidence.manifest 為準。
4. evidence.data 只包含選取 capability；不可假設未出現資料等於 0。
5. limitations 與 error 必須保留。
6. continuation.fill_plan 是建議的 bounded 補資料方式；consumer 不可直接
   呼叫內部 refresh function。
7. MCP include_raw 已棄用；v4 下是 no-op。縮小 payload 必須用 selection。
